# PSOC&trade; Edge MCU: I2C controller EzI2C target

This code example demonstrates the use of the I2C controller with an EzI2C target on Arm&reg; Cortex&reg;-M33 CPU on PSOC&trade; Edge MCU. The I2C controller is configured to send command packets to control a user LED on the target. Both the target and the controller can be configured on the same kit or on different kits.

This code example has a three project structure: CM33 secure, CM33 non-secure, and CM55 projects. All three projects are programmed to the external QSPI flash and executed in Execute in Place (XIP) mode. Extended boot launches the CM33 secure project from a fixed location in the external flash, which then configures the protection settings and launches the CM33 non-secure application. Additionally, CM33 non-secure application enables CM55 CPU and launches the CM55 application.

## Hardware setup

This example uses the board's default configuration. See the kit user guide to ensure that the board is configured correctly.

Ensure the following jumper and pin configuration on the board.
- BOOT SW must be in the HIGH/ON position
- J20 and J21 must be in the tristate/not connected (NC) position (for the PSOC&trade; Edge E84 Evaluation Kit)
- All SW8 DIP switches in OFF position (for the PSOC&trade; Edge E846 Evaluation Kit)

Connect the I2C_SCL and I2C_SDA pins of the controller with I2C_SCL and I2C_SDA pins of the target using the jumper wires (use either single kit or two different kits for controller and target).

**Table 1. I2C_SCL/I2C_SDA pin assignment**

SPI controller/target|  I2C_SCL   |  I2C_SDA
:--------------:| :--------: | :--------:
Controller |   P8_0 (I2C.SCL)   |    P8_1 (I2C.SDA)
Target  |   P17_0 (UART.Rx)  |    P17_1 (UART.Tx)

## Operation

See [Using the code example](docs/using_the_code_example.md) for instructions on creating a project, opening it in various supported IDEs, and performing tasks, such as building, programming, and debugging the application within the respective IDEs.

1. Connect the board to your PC using the provided USB cable through the KitProg3 USB connector

2. Open a terminal program and select the KitProg3 COM port. Set the serial port parameters to 8N1 and 115200 baud

3. Configure the code example to work in one of the following combinations:

      1. Both the controller and the target is on the same kit

      2. The controller only on the kit

      3. The target only on the kit

   By default, the code example is configured to work in the `I2C_BOTH_MODE` mode. In the *main.c* file, change the value of the `I2C_MODE` macro to `I2C_MODE_CONTROLLER` or `I2C_MODE_TARGET` for controller only or target only configurations

   Ensure to use jumper wires to establish a connection between the controller and the target on the kit. See the [Hardware setup](#hardware-setup) for the pin assignment

   When using the code example only in target or controller mode, use other board in controller mode or target mode accordingly for I2C communication

4. After programming, the application starts automatically. Confirm that the UART terminal displays the following:

   Note that the following image shows the output when configured for `I2C_BOTH_MODE`

   **Figure 1. Terminal output on program startup**

   ![](images/terminal-i2c-controller-ezi2c-target.png)

5. Observe that the USER LED1 on the kit blinks at 1 Hz during I2C communication
